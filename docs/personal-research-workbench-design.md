## 一、体检结论

先把事实摆清楚，后面所有设计都建立在这张表上。

| 维度 | 实测值 | 判断 |
|---|---|---|
| 后端核心 `tdxback/` | 133 文件 / 42,675 行 | 能力完备，远超「够用」 |
| API 路由 | **197 个**（README 记 35） | 严重超配，文档已失真 |
| 前端页面 | **22 个**（pages/ 下 22 个文件） | 决策链被切成碎片 |
| 前端 api.ts | 单一文件 **3,169 行** | 耦合信号 |
| 测试 | 78 文件 / **1,078 个 test 函数** | 这是全项目最被低估的资产 |
| 静默失败 | **539 处 `except Exception`，117 处直接 pass** | 结论可能残缺而用户不知 |
| 数据 | 40 GB（`data/`） | 有真实沉淀，不可重建 |
| 设计文档 | 25+ 份 PRD/TECH | 每个模块自带一套，说明是叠加生长 |
| 预判验证闭环 | **「兑现/预判/命中率/准确率」全文 0 次出现** | 最大缺口 |

**核心诊断：问题不是缺能力，是缺收敛。**

每加一个分析维度就加一个页面，22 个页面每个都在「陈列事实」，但没有一个页面回答「所以今天我该做什么」。用户被迫在脑内做拼接——这一点项目自己的 `docs/LINKAGE-DESIGN.md` 已经写明白了：

> 「用户晚上复盘时要在脑子里手动拼接『温度 → 哪个板块强 → 板块对应哪只 ETF → 板块里买谁』，这正是『一站式』要消灭的断裂。」

文档诊断对了，但解法是「再加一个 LinkagePage」，于是变成第 23 个页面。

## 二、可复用轮子

## 三、七个「好 idea，但有缺陷」

这一节是你最关心的部分。每条都是「想法值得留，实现要改」。

### 1. L1 五维状态机：思想对，阈值是魔数

**想法**：用 `进攻/防守/观望` 三态 + 五维评分 + 决策检查清单，一句话回答「今天能不能做」。
**缺陷**：
- 阈值全是硬编码魔数（温度 ≥15% 判进攻、<8% 判防守、主线 ≥3），没有任何校准依据，用户无法调也不知从哪来
- **同一个「温度」两套分档**：`zone` 用 50/25/10，`state` 用 15/8。温度 12% 时 zone 说「拉锯区」，state 可能说「进攻」——自相矛盾
- 成交额分位用**成交量**近似（代码注释承认腾讯指数 K 线无 amount），量额混用，放量不涨会误判为资金进场
- `_append_score` 每天读写 JSON 只留 250 天，新装时前 5 天 `sentiment_pctile` 用温度分位兜底 → 同一指标两种口径
- 建议仓位「50%~75%」硬编码，与用户风险偏好无关

**借鉴方式**：保留「状态机 + 检查清单」这个形态（这是全项目最好的产品抽象），但：
- 阈值改为**配置文件 + 历史分位校准**，每个阈值标注「当前值 / 该值的历史分位 / 改了会怎样」
- zone 与 state **合并为单一口径**，不允许两套
- 成交额缺失时明确标注「本条依据不完整」，而不是静默用成交量顶替

### 2. 五层体系：分层对，但层间靠 try/except 糊

**想法**：L1 环境 → L2 轮动 → L3 选股 → L4 风控 → L5 主线，完整决策链。
**缺陷**：`temperature.py` 里有 5 处 `except Exception: pass`，任一模块挂掉就静默降级为 `None`。全项目 539 处 `except Exception`、117 处直接 pass。**结果是：系统可能在一个模块已经失败的情况下，照常给出一份看起来完整的判断。**

**借鉴方式**：分层保留，但加一道**依赖完整性门禁**：
- 每层输出附带 `complete: true/false` 与缺失项清单
- 任一层不完整，首页顶部显式标注「今日判断不完整：缺少 X」，并禁用「操作建议」格
- 宁可说「我不知道」，也不给一份残的判断

### 3. 联动图谱：设计最好，只做了一半

**想法**：`大盘 → 板块 → ETF → 个股` 四层漏斗，自顶向下归因。
**缺陷**：只完成了数据地基（板块强度评分），「机会清单」是静态输出；文档结尾写的「次日验证哪个板块判断兑现」**没有任何实现**（全后端 0 次出现「兑现」）。
**借鉴方式**：这是首页骨架的最佳候选——直接把漏斗做成「今日一页」的主干，并把兑现对账补成闭环（见第六节）。

### 4. 公式回测：承诺与实际不符，被迫双轨

**想法**：粘贴通达信源码就能回测，不用转写代码。
**缺陷**：函数库只有 33 个，缺 `STD`。结果经典 BOLL 公式**根本跑不了**，于是布林策略被用 Python 硬编码重写（`boll_band.py` / `band_strategy.py` / `curved_band.py`）。

形成**两套互不相通的策略表达**：公式路径能力受限，Python 路径能力全但用户「不写代码」用不上。更危险的是两套口径可能不一致，同一策略两种写法给出不同信号，而没人对账。

**借鉴方式**：
- 补函数到 45+，让 90% 实战公式可直接跑
- **双轨一致性对账**：同一策略允许公式/Python 两种实现，但必须过同一把尺——同参数同标的下信号一致率 ≥99%，否则拒绝上线

### 5. 策略看板 M1/M2 闸门：机制好，但只服务硬编码策略

**想法**：买卖条件拆成逐日闸门（M2 买入闸门、E1–E7 卖出条件），信号可解释。
**缺陷**：只覆盖少数内置策略，用户自己写的策略接不进来。等于「可解释性」只属于开发者。
**借鉴方式**：抽象成通用管道 `策略 → 逐日信号 → 自动跟踪`，任何策略（公式或 Python）都走同一条管道，自动获得可解释性与跟踪能力。

### 6. 22 个页面：每页都对，合起来错

**想法**：每个分析维度一个页面，各自做深。
**缺陷**：决策链被切成碎片。`DailyPage` / `ReviewPage` / `HistoryPage` / `PanoramaPage` 四个页面都在讲复盘，用户不知道从哪进。
**借鉴方式**：页面合并不删能力——22 页压成 3 个入口，其余降级为下钻页（见第七节映射表）。

### 7. 数据铁律：这条必须原样继承

**想法**：全部真实数据、绝不模拟；数据不完整不生效；盘中冻结昨日快照供对照。
**缺陷**：无。这是项目最正确的一条纪律，QuantLab 也守着同样的规矩。
**借鉴方式**：原样继承，并在界面上显式呈现「数据日期 + 调度阶段 + 完整性状态」，让用户随时知道看到的是哪一天、全不全。

## 四、聚焦设计：三入口

从 22 个页面收敛为 3 个入口 + 下钻。原则：**入口回答决策，下钻满足好奇。**

| 入口 | 回答什么 | 使用频率 | 对应原页面 |
|---|---|---|---|
| **今日一页** | 今天能不能做 / 做什么 / 不做什么 | 每日 1 次 | Daily + Panorama + Linkage + Review + Ops |
| **观察池** | 值得埋伏什么，它现在到哪一步了 | 每日 1 次 | Risk + Stock + Monitor |
| **策略实验室** | 我这套方法到底行不行 | 每周 1 次 | Backtest + Batch + Strategies + Lifecycle + StrategyDash + CompleteStrategy + Gate + Mining |

折叠为设置项：Intraday / Realtime / Overnight / Swing / Settings / History。
不再新增顶层页面——**新能力一律以「今日一页的一格」或「下钻」形态存在**。

## 五、今日一页：七问七格

这是整个设计的核心。每个格子必须固定四件套，缺一不可：

1. **结论**（一句话，可执行）
2. **证据**（≤3 条，每条可点回原始数据）
3. **失效条件**（什么情况下这个结论就是错的）← 最重要，防事后诸葛
4. **与昨日对比**（昨天怎么说的，变了吗，为什么变）

| 格 | 你的问题 | 结论形态 | 失效条件示例 |
|---|---|---|---|
| ① 环境 | 现在市场怎么样 | 进攻 / 观望 / 防守 + 仓位区间 | 温度跌破 X% 或指数失守 MA60 |
| ② 主线 | 什么好，什么不好 | 板块 ABCD 榜 + 前 3 名 + 退潮名单 | 主线板块 3 日内净流出居前 |
| ③ 时机 | 什么有买卖点 | 今日触发信号的标的数 + 代表 3 只 | 信号标的次日集体低开 >2% |
| ④ 候选 | 什么值得埋伏观察 | 观察池新增 / 晋级 / 淘汰 | 3 日内未启动则降级 |
| ⑤ 风险 | 我持的有什么不对 | 破位 / 转弱 / 减仓信号 | —（风险格只报不猜） |
| ⑥ 对账 | 什么符合预期什么不符合 | 昨日预判命中/未命中 + 错在哪一环 | —（对账格不设失效条件） |
| ⑦ 明日 | 未来会怎样 | 明日情景（乐观/中性/悲观）+ 触发条件 | 任一情景的触发条件被反向击穿 |

设计要点：

- **格子有优先级**：①⑥ 永远在最上面。环境不对，后面的选股全是白费；昨天的错没复盘，今天的判断不会更准
- **格子可空但不可假**：数据不全就写「依据不完整」，不填占位
- **每格只有一个结论**：不允许「多个指标供参考」。要参考就下钻
- **⑥ 对账格是每日必看**：这是唯一让人「越用越准」的机制

## 六、最大缺口：预判 → 验证闭环

这是 `tdx-backtest` 完全没有、而你的需求反复指向的东西（「什么符合预期什么不符合」「未来会怎样」）。

没有它，工作台只是一堆实时指标；有了它，才是一台**能校准自己判断力的机器**。

```
收盘后生成预判卡
  ├─ 市场状态预判（明日进攻/观望/防守）
  ├─ 主线预判（哪 2-3 个方向延续）
  ├─ 候选预判（观察池里谁会启动）
  └─ 失效条件（什么情况说明我错了）
        ↓
次日盘中/收盘 自动对照
        ↓
收盘对账打分
  ├─ 环境判断：对 / 错
  ├─ 方向判断：对 / 错
  ├─ 标的判断：对 / 错
  └─ 归因：错在环境？方向？还是标的？
        ↓
沉淀为「我的判断力画像」
  ├─ 进攻态下我的判断命中率
  ├─ 震荡态下我的判断命中率
  └─ 我最常犯的错：把反弹当反转 / 追高 / 过早离场
```

**为什么这条比任何指标都重要**：A 股个人投资者真正缺的不是信息，是「知道自己哪一步判断错了」。指标堆到 100 个也不会告诉你这件事，只有强制对账会。

**实现成本低**：所有原始数据（板块榜、涨停池、个股涨跌、快照存档）`tdx-backtest` 都已有，缺的只是「预判落库 + 次日对账 + 归因统计」三张表和一次定时任务。

**归因颗粒度**是三段式，不允许笼统说「判断错了」：
- 环境错 → 明明转弱却判进攻
- 方向错 → 环境判对但主线选错
- 标的错 → 方向对但选错股
- 时机错 → 都对但信号早/晚一天

这个四分类直接告诉你「该改哪一环」，而不是「水平不行」。

## 七、观察池：把「埋伏」变成可管理的东西

回答「什么值得关注埋伏观察」——用状态机，不用列表。

| 状态 | 进入条件（可计算） | 失效条件（可计算） | 最长停留 |
|---|---|---|---|
| 待观察 | 板块 B 档以上 + 个股评分 ≥70 | 板块降至 D 档 | 10 交易日 |
| 埋伏 | 待观察中缩量回踩 MA20 不破 | 放量破 MA20 | 15 交易日 |
| 启动确认 | 埋伏中放量突破前高 | 突破后 3 日不站稳 | — |
| 持有 | 启动确认后 | 破 10 日线 / 出现 E 类卖出条件 | — |
| 移出 | — | — | 必填原因 |

三条硬规则：

1. **每个状态都有「最长停留」**——防止标的一直赖在池里，把池子变成第二个自选股
2. **移出必填原因，四选一**：逻辑破了 / 触发太慢 / 被更好的替代 / 我判断错了
3. **移出记录进语料库**——「我判断错了」的样本积累起来，就是第七节判断力画像的原料

第三点尤其关键：绝大多数人只有「买入记录」，没有「我为什么放弃」的记录。后者才是提高判断力的样本。

## 八、策略实验室：从「一次性回测」到「持续跟踪」

回答「我这套方法到底行不行」。

一个策略 = 一份源码 + 一份验证档案 + 一条实盘跟踪线。

**验证档案（五道闸，任一道不过就不许上线）**：

| 闸 | 检查 | 数据来源 |
|---|---|---|
| 1 未来函数 | 静态扫描 + 加数据重算不变性 | `future_scan.py` + 动态检测 |
| 2 样本内外 | 前 70% / 后 30% 表现衰减 < 阈值 | `split_test.py` |
| 3 普适性 | ≥30 只标的上正期望占比 | `batch.py` |
| 4 牛熊分段 | 牛/熊/震荡三段都不亏 | `phase_test.py` |
| 5 双轨一致性 | 公式版与 Python 版信号一致率 ≥99% | 新建 |

**结论只允许三档**：可用 / 存疑 / 不可用。不允许「给你 20 个指标自己看」——那是把判断责任推回给用户。

**上线后不是结束，是开始**：每日自动记录该策略的信号，跟踪 T+1 / T+5 / T+10 收益，累积成实盘曲线。三个月后如果与回测偏差过大，自动降级为「存疑」。

这一步把「回测」从一次性验收变成持续体检——也是 `tdx-backtest` 有闭环设计但只覆盖内置策略的部分，通用化后你能用自己的策略。

## 九、页面裁剪映射（22 → 3）

| 目标入口 | 吸收 | 处理方式 |
|---|---|---|
| 今日一页 | DailyPage, PanoramaPage, LinkagePage, ReviewPage | 合并为七格；四页的明细全部转为格内下钻 |
| 观察池 | RiskPage, StockPage, MonitorPage | 合并为状态机列表 + 单标的下钻 |
| 策略实验室 | BacktestPage, BatchPage, StrategiesPage, LifecyclePage, StrategyDashPage, StrategyDashIndexPage, CompleteStrategyPage, GatePage, MiningPage | 合并为一个页面 + 五个 tab（源码 / 验证 / 批量 / 跟踪 / 版本） |
| 折叠进设置 | IntradayPage, RealtimePage, OvernightPage, SwingPage, SettingsPage, HistoryPage | 保留能力，从导航移除；盘中需求改由今日一页的时间态切换承载 |

**导航从 22 项降到 3 项**，其余全部下钻可达。任一能力不删，只改变可达路径。

## 十、落地路径

不推倒重来。`tdx-backtest` 的引擎和数据层质量足够，改造集中在「加闭环 + 减页面」。

| 期 | 目标 | 交付 | 验收标准 |
|---|---|---|---|
| **一期** | 补闭环 | 预判卡落库 + 次日对账 + 四段归因 | 连续 20 个交易日跑通，能回答「这 20 天我的判断命中率是多少、错在哪一环」 |
| **二期** | 收页面 | 今日一页 + 观察池上线，导航 22→3 | 每日复盘从「翻 5 个页面」变成「看 1 页 + 按需下钻」，用时 ≤15 分钟 |
| **三期** | 统一策略 | 函数库扩到 45+、五道闸、双轨对账、实盘跟踪 | 任意自写公式/策略走完五道闸并自动进入跟踪 |

一期为什么先做闭环：它不依赖任何新数据，改动最小，但**只有它能直接回答你最难的那一问**。而且它会立刻暴露已有判断逻辑的问题——二十天对账比任何代码审查都准。

## 十一、风险

| 编号 | 风险 | 概率 | 影响 | 应对 |
|---|---|---|---|---|
| RK-01 | 一期对账跑出来发现原有阈值全错，需要重校准 | 高 | 中 | 这恰恰是价值所在。预留校准期，先把「对账」跑通再调阈值 |
| RK-02 | 22→3 收敛后，依赖旧页面的习惯被打断 | 中 | 中 | 下钻路径必须完整可达；保留 URL 兼容，旧链接重定向到对应下钻 |
| RK-03 | 539 处静默 except 导致对账数据本身不可信 | 高 | 高 | 对账链路先做「完整性门禁」，只统计 complete=true 的日期 |
| RK-04 | 公式函数扩展引入语义偏差（与通达信不一致） | 中 | 高 | 每补一个函数，必须附一个与通达信逐值比对的对账用例 |
| RK-05 | 归因四分类边界模糊（环境错还是方向错） | 中 | 中 | 归因规则写死优先级：环境 > 方向 > 标的 > 时机，按序判定 |

## 十三、一句话总结

`tdx-backtest` 的问题从来不是「做不到」，而是**做太多、说得太散、从不回头验证自己**。

它已经有 42,675 行引擎、1,078 个测试、40GB 真实数据——这些够撑起一个非常好的个人投研工作台。

缺的只有三件：**一页能下判断的界面**、**一个能被证伪的预判**、**一条能持续跟踪的策略**。
