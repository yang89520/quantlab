# 数据口径约定

> 适用：所有从外部接口取数、并用于指标计算或跨标的比较的代码路径。
> 修改 `lib/sources/` 下任何适配器前请先读这份。
> 可复现的核对命令：`node tools/reconcile.js --n 20`

## 为什么需要这份文档

同一个价格，不同接口给出来可能不一样。差异分三类，处理方式完全不同：

| 类型 | 例子 | 是否可接受 | 处理方式 |
|---|---|---|---|
| **数据错误** | 前复权早期价格为负 | ❌ 绝对不行 | 不用该口径 |
| **算法差异** | 两家分红处理不同，相差 1% | ✅ 必然存在 | 单源使用，禁止拼接 |
| **单位差异** | 成交量「股」vs「手」 | ✅ 可换算 | 入口统一折算 |

把这三类混在一起谈，就会得出"数据不可靠"的错误结论。实际测试下来：
**原始价完全一致（0.0000%），差异全部来自复权算法。**

## 一、时间窗口：10 年限制的是「单次跨度」

接口报错原文：

```
code=1003  Parameter value out of range: [start, end] must span at most 10 years
```

这句话的意思不是「只能取近 10 年」，而是**单次请求的 start 到 end 跨度不能超过 10 年**。
更早的历史用分段请求拼接即可，实测有效：

| 请求 | 结果 |
|---|---|
| 2006-01 → 2026-11（20 年，单次） | `code=1003` 报错 |
| 2006-01 → 2015-12（10 年内） | 119 根月线 |
| 2006-01 → 2026-11（自动切 3 段） | **250 根月线，含 2006 年全部数据** |

实现见 `lib/sources/adapters/fuyao.js` 的 `splitSegments()`：

- 每段 9 年（留出闰年与边界余量）
- 相邻段在边界处重叠一个时间点，用 `Map` 按日期去重
- 默认窗口 8.9 年，**恰好落在单段内**，避免默认路径多一次往返

## 二、复权：接口的 forward 是坏的

这是本次最重要的发现。

### 现象

`adjust=forward` 在长跨度上会返回**负价格**：

```
600519.SH  2006-01  forward = -304.31   （原始价 47.24）
           2010-01  forward = -190.02
           250 个月里 125 个月为负，2016-06 之前全部为负
```

负价格不可能是真实数据。进一步验证发现，forward 与 backward 的比值在 **6.54 ~ 294** 之间波动，
不是等比关系 —— 说明它用「减累计分红」处理除权，而不是「除权因子累乘」。
两者在累计分红超过股价时必然出负值。

### 三种口径的实测对比

以 600519.SH 2019-12 为例：

| 口径 | 收盘价 | 说明 |
|---|---|---|
| `none`（不复权） | 1183.00 | 真实成交价 |
| `backward`（后复权） | 7001.91 | 以上市首日为基准累乘 |
| `forward`（接口原生） | 923.67 | ❌ 多做了一次扣减 |
| `forward`（backward 重建） | 857.06 | ✅ 数学等价于标准前复权 |

### 正确做法

前复权的定义是「把历史价格调整到与最新价可比」，等价于：

```
forward[t] = backward[t] / backward[last] × none[last]
```

后复权 = 原始价 × 累计因子，除以最新累计因子再乘最新真实价，就是前复权。
这个式子恒为正，长历史可用。实现见 `rebuildForward()`。

各口径的适用场景：

| 用途 | 用什么 | 理由 |
|---|---|---|
| 计算指标（偏离/箱位/量位） | `backward` 重建的 forward | 恒正、长历史可用 |
| 展示价格给用户 | `none` | 真实成交价，用户认这个数 |
| 计算成交量 | `none` | 见下一节 |

## 三、成交量：backward 会把量除掉

这一条极易漏掉，但它直接影响「量位」。

实测 600986.SH 2026-08-10：

| 口径 | volume | close | 量 × 价 | 与成交额之比 |
|---|---|---|---|---|
| `none` | 64,977,422 | 8.03 | 5.22 亿 | **1.003** ✓ |
| `forward` | 64,977,422 | 8.03 | 5.22 亿 | **1.003** ✓ |
| `backward` | 11,713,215 | 45.88 | 5.37 亿 | 1.034 |

`backward` 为了维持「成交额 = 量 × 价」，把**成交量也除以了复权因子**（64,977,422 → 11,713,215，差 5.55 倍）。

如果重建序列时沿用 backward 的成交量，会出现：

- 价格缩回真实水平（8.03）
- 成交量却还是被除过的值（1171 万）
- 结果「量 × 价」比真实成交额小 5.5 倍

对公式里的 `量位 = (V - LLV(V,30)) / (HHV(V,30) - LLV(V,30)) × 100`，
由于复权因子在每次分红时跳变，这种失真**不是恒定的**，会让地量判断整体偏移。

**结论：价格用 backward 重建，量、额一律取 none 的真值。**
取不到 none 时按价格因子反向缩放兜底（`volume / k`），并记日志。

## 四、跨源不可混用

原始价一致，但**复权序列有差，且无法消除**。抽样 6 只实测：

| 代码 | 名称 | 原始价偏差 | 复权平均偏差 | 复权最大偏差 |
|---|---|---|---|---|
| sz300308 | 中际旭创 | 0.0000% | 0.50% | 0.69% |
| sz300502 | 新易盛 | 0.0000% | 0.42% | 0.55% |
| sh688256 | 寒武纪 | 0.0000% | 0.02% | 0.04% |
| sh688981 | 中芯国际 | 0.0000% | 0.00% | 0.00% |
| sh601899 | 紫金矿业 | 0.0000% | 2.42% | 3.76% |
| sz300750 | 宁德时代 | 0.0000% | 2.71% | 4.24% |

有分红的票偏差大（宁德 2.7%），无分红的票几乎为零（中芯 0.00%）。
这是两家分红算法的固有差别，**不能通过乘一个常数修正**。

### 对指标的实际影响

同样按日期对齐后各算一遍：

| 指标 | 两源最大差异 | 原因 |
|---|---|---|
| 箱位 | **0.000** | 分子分母同乘因子，比值不变 |
| 量位 | **0.000** | 只用成交量，与复权无关 |
| 偏离 60 日均线 | 0.00 ~ 2.03 | 窗口内含分红时，均线权重变化 |

所以：
- `箱位<20`、`量位<20` 两个条件**不受复权口径影响**
- 只有 `偏离<-10%` 会受影影响，这也是同一份池子在两种口径下相差 2~3 只的全部来源

实测三版对比（同一份 5221 只、同一公式、2026-10 命中）：

| 版本 | 10 月命中 | 拥挤度 |
|---|---|---|
| 接口原生 forward（量正确） | 219 | 4.19% |
| backward 价格 + **backward 量**（错） | 222 | 4.25% |
| backward 价格 + **none 量**（正确） | **221** | **4.23%** |

### 铁律

> 一个序列只从一个源取全，派生指标也从同一序列算。
> 跨源只在「该源整体不可用」时整体降级，**绝不逐只拼接**。

选股链路把这一点显性化了：结果里的 `sourceMix` 字段给出源分布，
主源占比低于 95% 时标 `degraded`。实测 `fuyao 5220 / ths 1`，占比 99.98%，
那 1 只是批量接口没覆盖到的票，走日线链路兜底。

## 五、板块资金流：换源与匹配方式

原源东财 `clist f62` 已熔断（连续 100 次失败），改用新浪：

```
GET /quotes_service/api/json_v2.php/MoneyFlow.ssl_bkzj_bk?page=1&num=500&sort=netamount&asc=0&fenlei=
  fenlei=0 行业（48 个）   fenlei=1 概念（181 个）
```

关键优势：返回的 `category` 字段（`new_jxhy` / `gn_rzrq`）**就是新浪板块代码**，
与板块字典同体系，可以按 code 精确匹配 —— 实测 **220/221 命中（99.5%）**，
只有「次新股」对不上。东财那套「按名称去后缀猜」的匹配方式命中率极低，已降为备用。

### 口径差异（必须知道）

| 字段 | 含义 | 与东财的差别 |
|---|---|---|
| `netamount` | 净流入额（大单口径），单位元 | 东财 f62 是「主力」= 超大单+大单，量级相近但边界不同 |
| `ratioamount` | 净流入占比（小数） | 跨板块可比，比净额更稳，建议分位用它 |
| `avg_changeratio` | 板块涨跌幅（小数） | — |
| `turnover` | 成交额，单位**亿元** | — |

因为量级与东财不同，**切换源前后的净流入数值不可直接比较**，
历史分位需要重新累积。

## 六、核对方法

```bash
node tools/reconcile.js --n 20      # 抽样 20 只，输出三层核对报告
node tools/reconcile.js             # 默认 8 只
```

脚本做三件事：

1. **原始价**：fuyao `none` vs 新浪不复权，逐日比对，阈值 0.05%（应为 0.0000%）
2. **复权序列**：fuyao 重建 forward vs ths forward，只测量不判错，历史范围 0.4%~2.8%
3. **派生指标**：按日期对齐后各算箱位/量位/偏离，箱位与量位应完全相同

退出码非 0 表示存在硬性不一致（原始价错、负值、指标错位）。

配套单测：`node tests/unit/fuyao.test.js`（13 条，纯逻辑不联网）。

## 七、已知限制

1. **沙箱环境缺 `localDb.marketDb`**，板块强度无法离线重算，会整体降级。
   资金流本身已写入 `data/sectors/dict.json`（220 个板块带净额与净占比），
   但强度评分需要成分股日线，这一步依赖上游行情库。
2. **扶摇单 key**，多环境需各自申请；批量上限 10 只/次。
3. **次新股**天然凑不够 108 根月线，会被判 `K 线不足`（本次 307 只，占 5.9%），
   这是数据事实，不是取数失败。
