# 前端审查与高保真设计规范

> 审查对象：`public/` 现有 2 页（分析台 `index.html`、选股器 `screen.html`）+ 全套 CSS/JS
> 设计对象：`docs/dev/06-phase4-ui.md` 定义的「今日一页」七格
> 方法：通读 CSS/HTML/JS → 量化计算对比度与字号分布 → 按 WCAG 2.2 AA 逐项核验

---

## 一、缺陷清单

按严重度分级。**每条都有代码位置与实测数值，不是主观感受。**

### 🔴 阻断级（键盘用户无法完成核心操作）

| # | 缺陷 | 证据 | 影响 |
|---|---|---|---|
| A1 | **`screen.css` 移除焦点轮廓但不提供替代** | `screen.css:64`、`:72` 均为 `:focus{outline:none; border-color:#33507E}` | 键盘用户看不到焦点在哪，等于无法操作 |
| A2 | **全站无 `:focus-visible`** | 三个 CSS 文件中 0 处 | 鼠标点击与键盘聚焦无法区分，焦点环要么没有、要么一视同仁地难看 |
| A3 | **弹窗不还原焦点** | `watchlist.js:579` `closeSheet()` 只移除 class，不 `focus()` 回触发元素 | 关闭弹窗后焦点落到 `body`，键盘用户需从头 Tab |
| A4 | **弹窗无焦点陷阱** | `watchlist.js:544` `showSheet()` 仅在 `cfg.autofocus` 时聚焦输入框 | `role="dialog" aria-modal="true"` 声明了模态，但 Tab 可穿到背景，语义与行为不符 |

### 🟠 高（信息不可读 / 语义错误）

| # | 缺陷 | 证据 | 影响 |
|---|---|---|---|
| B1 | **41 处字号小于 11px，最小 9px** | 9px×3、9.5px×11、10px×10、10.5px×17 | 手机端几乎不可读；Mac 高分屏也只是"勉强" |
| B2 | **`--tx3` 对比度 3.86:1，未达 AA 4.5** | `#67738A` on `#0E141E` = 3.86 | 而它恰好被用在 41 处小字上——**最小字号 × 最低对比度**，最伤眼的组合 |
| B3 | **Tab 无 `role="tablist"/tab/tabpanel`** | `index.html:123` 容器为 `<div class="tabs">`，由 JS 生成子项 | 读屏软件无法识别这是选项卡，也不会播报"第 3 项，共 40 项" |
| B4 | **Tab 不支持方向键切换** | JS 中仅有 click 绑定 | WAI-ARIA 选项卡模式要求 ←/→ 导航 |
| B5 | **弹窗缺 `aria-labelledby`** | `index.html:253` 有 `role="dialog"`，但标题是 `div.sh-tt`，未与弹窗关联 | 读屏进入弹窗时不播报标题 |

### 🟡 中（体验与一致性）

| # | 缺陷 | 证据 | 影响 |
|---|---|---|---|
| C1 | **无 `prefers-reduced-motion` 适配** | 0 处；但 `.tab` 有 `transition:.18s`、多处 `transform` 动效 | 前庭敏感用户无法关闭动效 |
| C2 | **无跳过导航链接** | 0 处 | 键盘用户每次都要 Tab 过整个头部 |
| C3 | **无 `sr-only` 工具类** | 0 处 | 无法为纯图标按钮补隐藏文本（虽然已用 `aria-label` 部分弥补） |
| C4 | **中文字体上使用 `text-transform:uppercase`** | `style.css:29` `.brand p`、`.sec-t`、`.card-hd h2` | 对中文无视觉效果，但会放大 `letter-spacing:1.4px` 造成的字距松散 |
| C5 | **`--tx3` 同时用于"标签"和"禁用态"** | 语义混用 | 禁用态与普通标签视觉无差异，用户分不清"淡"是次要还是不可用 |

### 🟢 低（打磨项）

| # | 缺陷 | 说明 |
|---|---|---|
| D1 | 移动端断点仅 1080px 一处 | 320–1079px 全部单列，平板竖屏浪费空间 |
| D2 | 无 `:active` 按压反馈 | 只有 `:hover`，触屏点按无反馈 |
| D3 | 滚动条样式仅 WebKit | Firefox 下为默认样式，与整体不协调 |

## 二、设计令牌（修复后）

**原则：保留现有品牌色与深色基调，只修对比度与字号，不推翻重来**——现有配色气质是对的，问题在细节。

### 2.1 颜色

| 令牌 | 原值 | 新值 | 对比度（vs 卡片 `#0E141E`） | 用途 |
|---|---|---|---|---|
| `--bg` | `#080B11` | 不变 | — | 页面底 |
| `--bg2` | `#0B1018` | 不变 | — | 卡片渐变底 |
| `--card` | `#0E141E` | 不变 | — | 卡片主色 |
| `--card2` | `#121A26` | 不变 | — | 卡片内嵌层 |
| `--line` | `#1A2230` | 不变 | — | 分割线 |
| `--line2` | `#232E3F` | 不变 | — | 描边 |
| `--tx` | `#E8EDF5` | 不变 | **16.75** | 主文本 |
| `--tx2` | `#9AA6B8` | 不变 | **7.49** | 次文本 |
| `--tx3` | `#67738A` | **`#828FA5`** | 3.86 → **5.65** ✅ | 三级文本（标签/说明） |
| `--tx-disabled` | — | **新增 `#5A6478`** | 3.0（仅用于禁用态，不承载信息） | 区分"淡"与"不可用" |

**注意**：涨用红、跌用绿是 A 股约定，**与欧美相反**，保持不变。

### 2.2 字号刻度

**硬规则：正文最小 12px，11px 仅限带 `font-weight:600` 的徽标，禁止 9–10.5px。**

| 层级 | 字号 | 字重 | 行高 | 用途 |
|---|---|---|---|---|
| `--fs-hero` | 32px（移动端 26px） | 700 | 1.15 | 环境结论大字 |
| `--fs-h1` | 20px | 700 | 1.3 | 页面标题 |
| `--fs-h2` | 16px | 600 | 1.4 | 卡片标题 |
| `--fs-h3` | 14px | 600 | 1.5 | 小节标题 |
| `--fs-body` | 14px | 400 | 1.6 | 正文 |
| `--fs-sm` | 13px | 400 | 1.55 | 次要正文 |
| `--fs-xs` | 12px | 400 | 1.5 | 标签、说明 |
| `--fs-badge` | 11px | 600 | 1.2 | **仅徽标**（如 A/B/C/D 档） |

数字一律 `font-variant-numeric: tabular-nums`，避免跳动。

### 2.3 间距与圆角

间距用 4 的倍数：`4 / 8 / 12 / 16 / 20 / 24 / 32 / 40`。
圆角：`--r-sm:8px`（徽标）、`--r-md:12px`（内嵌块）、`--r-lg:16px`（卡片）。

## 三、布局与断点（移动优先）

| 断点 | 栅格 | 七格排布 |
|---|---|---|
| **320–575**（小屏手机） | 1 列 | ①→⑥→②→③→④→⑤→⑦ 纵向，间距 12px |
| **576–767**（大屏手机） | 1 列，间距 16px | 同上 |
| **768–1199**（平板） | 2 列 | ① 通栏；⑥ 通栏；②③/④⑤/⑦ 成对 |
| **≥1200**（桌面） | 12 列 | ① 占 7 + ⑥ 占 5；②③④ 各占 4；⑤⑦ 各占 6 |

**为什么 ① 与 ⑥ 置顶且最宽**：环境不对后面全白费；昨天的错没复盘，今天的判断不会更准。（与 `06` 文档一致）

`320px` 下必须验证：无横向滚动、无文字截断、按钮 ≥44×44px。

## 四、组件规格

### 4.1 格子（Cell）

```
┌─────────────────────────────────────┐
│ ① 环境            [进攻]            │  ← 索引 + 标题 + 结论徽标
│ 可顺势加仓，回踩不破可持              │  ← 结论（判断型为 h2 级，陈述型为 body）
│                                     │
│ 依据                                 │  ← 证据区（≤3 条）
│ · 指数站上 MA20   3421.5 > 3380.2 ✓ │
│ · 市场宽度        58%（阈值 40%）   ✓ │
│ · 量能            1.12×            ✓ │
│                                     │
│ ┌ 失效条件（仅判断型）─────────────┐ │
│ │ 跌破 MA20 · 宽度<40% · 量能<0.7 │ │
│ └────────────────────────────────┘ │
│                                     │
│ 昨日 观望 → 今日 进攻  [为什么变了]  │  ← 对比条
└─────────────────────────────────────┘
```

**判断型（①②③④⑦）**：四件套齐全，失效条件用带底色的块呈现，**空则整格标红边框**。
**陈述型（⑤⑥）**：无失效条件块，改用"事实标签"（如 `已发生`）说明其性质。

### 4.2 状态

| 状态 | 呈现 |
|---|---|
| 正常 | 上述完整结构 |
| 不完整 | 卡片顶部 3px 琥珀色条 + 一行「依据不完整：缺少 X」；结论降为 `--tx2`；**仍显示内容** |
| 无数据 | 整格降透明度至 0.5 + 居中「需 X 期功能」；**绝不显示 0 或占位数字** |
| 错误 | 红色左边框 + 「加载失败，点击重试」按钮 |

### 4.3 焦点环（全站统一）

```css
:focus-visible{
  outline:2px solid var(--focus);
  outline-offset:2px;
  border-radius:inherit;
}
/* 鼠标点击不显示焦点环 */
:focus:not(:focus-visible){ outline:none; }
```

对应 A1–A2：**任何可交互元素都必须有可见焦点**，且 `outline` 不得被 `none` 覆盖（若为美观覆盖，必须补等效替代）。

### 4.4 徽标（Chip）

| 类型 | 底色 | 文字 | 说明 |
|---|---|---|---|
| 进攻 attack | `rgba(246,70,93,.14)` | `--up2` | 红，顺势 |
| 观望 wait | `rgba(232,184,75,.14)` | `--gold` | 琥珀 |
| 防守 defend | `rgba(46,189,133,.14)` | `--dn2` | 绿，防守 |
| A 主攻 | 同上 attack | | 板块 A 档 |
| B 蓄势 | `rgba(53,208,208,.14)` | `--cyan` | 板块 B 档 |
| C 修复 | `rgba(154,166,184,.12)` | `--tx2` | 板块 C 档 |
| D 退潮 | `rgba(130,143,165,.10)` | `--tx-disabled` | 板块 D 档 |

**禁止只用颜色传达状态**：徽标必须同时有文字（"进攻"/"A 主攻"），不能只靠色块。

## 七、给开发的三条交接要点

1. **不要重写配色**。现有色板气质是对的，只需替换 `--tx3`/`--blue` 两个值 + 新增 `--focus`/`--tx-disabled` 两个令牌。
2. **`:focus-visible` 是新增的全局规则**，加在 `style.css` 最前面即可覆盖全站；`screen.css` 那两处 `outline:none` 必须删。
3. **七格的判据是"有没有失效条件"**，不是"长得好不好看"。判断型五格必须有，陈述型两格必须没有——这是 `06` 文档的硬要求，别为了"整齐"给风险格也编一个。
