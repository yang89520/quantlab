## 1. 先纠正一个容易误读的地方

产品设计总纲里写的是「22 页 → 3 入口」。**那是 tdx-backtest 的问题诊断，不是本项目的改造任务。**

本项目（QuantLab）现状只有 **2 个页面**：

| 现有页面 | 作用 |
|---|---|
| `public/index.html`（`/`） | K 线分析台 + 自选股侧栏 |
| `public/screen.html`（`/screen`） | 选股器（三层筛选） |

所以四期的真实工作是：**新建 3 个入口页面，并把已有 2 页重新定位为下钻/工具页**。

```
四期后导航（5 项）
├── 今日一页    /today      新建 · 默认首页
├── 观察池      /watch      新建
├── 策略实验室  /lab        新建
```

**不删任何现有能力**，只改变可达路径与默认落点。`/` 不再作为首页，改为重定向到 `/today`，但直接访问仍可用（保留书签兼容）。

## 2. 今日一页：七格

### 2.1 页面骨架

```
┌──────────────────────────────────────────────────────┐
│ 2026-11-13 周五      [数据完整 ✓]  [16:35 更新]        │  ← 状态条
├──────────────────────────────────────────────────────┤
│ ① 环境                                                │
│   进攻  仓位 50%~75%                                   │
│   依据：站上MA20 · 宽度58% · 量能1.12                   │
│   失效：跌破MA20 / 宽度<40% / 量能<0.7                  │
│   昨日：观望 → 今日：进攻  [变化理由]                    │
├──────────────────────────────────────────────────────┤
│ ② 主线        ③ 时机        ④ 候选                     │  ← 三格并排
├──────────────────────────────────────────────────────┤
│ ⑤ 风险                                                │
├──────────────────────────────────────────────────────┤
│ ⑥ 对账（昨日预判 vs 今日实际）                          │
├──────────────────────────────────────────────────────┤
│ ⑦ 明日三情景                                           │
└──────────────────────────────────────────────────────┘
```

**优先级固定**：① 永远在最上，⑥ 紧随其后。环境不对时后面的选股全是白费；昨天的错没复盘，今天的判断不会更准。

### 2.2 每格的强制四件套

七格分两类，要求不同——**别把陈述型格子硬塞失效条件，那会写出「这条事实什么情况下是假的」这种废话**：

| 类型 | 格子 | 强制项 |
|---|---|---|
| **判断型**（对未来下结论） | ① 环境 · ② 主线 · ③ 时机 · ④ 候选 · ⑦ 明日 | 四件套齐全，含**失效条件** |
| **陈述型**（只报已发生的事实） | ⑤ 风险 · ⑥ 对账 | 结论 + 证据 + 对比，**不设失效条件** |

四件套定义：

| 部分 | 要求 | 缺失时 |
|---|---|---|
| 结论 | 一句话，可执行 | 不许留空，宁可写「今日无结论」 |
| 证据 | ≤3 条，每条可点开看原始值 | 少于 1 条视为不完整，标黄 |
| 失效条件 | **仅判断型**：该结论在什么情况下是错的 | 判断型缺失则标红；陈述型不适用 |
| 与昨日对比 | 昨天怎么说的，变了吗，为什么变 | 首日无昨日数据时显示「首次运行」 |

**「失效条件」是本页存在的理由**。没有它，这一页就退化成第 23 个指标陈列页。
但也正因为如此，它只适用于**敢下预测的格子**——风险格说「这票破 MA20 了」是事实，不存在失效条件。

### 2.3 逐格规格

#### ① 环境

| 项 | 内容 |
|---|---|
| 结论 | 三态徽标 + 建议仓位区间。文案固定：进攻「可顺势，回踩不破可加」/ 观望「以观察仓为主，等共振」/ 防守「控总仓，等右侧信号」 |
| 证据 | 三条，对应 `env.parts` 的三个分项：趋势 / 宽度 / 量能。每条显示原始值与是否达标 |
| 失效条件 | `env.invalidIf` 全文列出，每条带当前值与阈值（如「宽度 58%（阈值 40%）」） |
| 对比 | 昨日的 verdict → 今日的 verdict，若变化则显示触发的分项变化 |

**必须显示 `score` 的拆解**：`62 = 趋势40 + 宽度18 + 量能4`。只给总分等于不可信（G8）。

#### ② 主线（依赖二期）

| 项 | 内容 |
|---|---|
| 结论 | A 档板块前 3 名（行业榜与概念榜**分开两个小栏**，不混排） |
| 证据 | 每板块给：动量分位 / 资金分位 / 宽度 / 持续性 四项中的前二 |
| 失效条件 | `mainline.invalidIf`：A 档板块次日跌出前 30% |
| 对比 | 昨日 A 档 → 今日 A 档，新增/掉出分别标注 |

`grade` 用固定四色徽标：A 主攻 / B 蓄势 / C 修复 / D 退潮。**不要自创名称**。
`degraded` 板块加灰色角标「资金数据缺失」。

#### ③ 时机

| 项 | 内容 |
|---|---|
| 结论 | 「今日触发信号 N 只」+ 代表 3 只（可点进分析台） |
| 证据 | 命中的策略名 + 信号类型（buy） |
| 失效条件 | 「信号标的次日多数低开 >2%」 |
| 对比 | 昨日信号今日表现（T+1 已回填的） |

依赖三期。三期未完成时该格显示：「需策略实验室就绪」，**不显示假数据**。

#### ④ 候选

| 项 | 内容 |
|---|---|
| 结论 | 观察池今日新增 / 晋级 / 淘汰各几只（三个数字） |
| 证据 | 每类各列最多 2 只，带当前状态 |
| 失效条件 | 「3 日内未启动则降级」 |
| 对比 | 昨日池内标的今日状态变化 |

点击跳 `/watch`。

#### ⑤ 风险

| 项 | 内容 |
|---|---|
| 结论 | 「持仓 N 只，其中 M 只触发风险信号」 |
| 证据 | 每只触发项：破位 / 转弱 / 减仓 |
| 失效条件 | **风险格不设失效条件**（只报事实，不做预判） |
| 对比 | 昨日风险数 → 今日风险数 |

**为什么风险格不设失效条件**：它是陈述事实（"这只破 MA20 了"），不是预测。强行加会变成废话。

#### ⑥ 对账（核心格）

| 项 | 内容 |
|---|---|
| 结论 | 「昨日判进攻，实际跌 0.62% → **环境错了**」或「判断正确」 |
| 证据 | 昨日预判要点 vs 今日实际值的逐项对照表 |
| 失效条件 | **不设**（对账是回看，不是预判） |
| 对比 | 最近 5 日命中序列：`✓ ✗ ✓ ✓ ✗` |

**这一格必须每天看**。它是唯一让人「越用越准」的机制。

点击展开：完整的四段归因明细（环境/方向/标的/时机）与 `judgmentScore`。

#### ⑦ 明日三情景

| 项 | 内容 |
|---|---|
| 结论 | 三个情景各一句话：乐观 / 中性 / 悲观 |
| 证据 | 每个情景的触发条件（可计算的条件，如「指数涨>0.8% 且宽度>55%」） |
| 失效条件 | 「三情景全未命中」→ 说明对明日的想象完全不靠谱，这本身是有价值的信息 |
| 对比 | 昨日的三情景今日实际落在哪一个 |

**三情景必须互斥且穷尽**：条件之间不能重叠，且要覆盖所有可能（用「其余」兜底）。

### 2.4 三种状态（每格都要实现）

| 状态 | 触发 | 表现 |
|---|---|---|
| **正常** | 数据完整 | 四件套齐全 |
| **不完整** | `dataComplete=false` | 该格顶部黄色横幅「依据不完整：缺少 X」，结论区显示为灰色但仍展示。**顶部状态条同步变黄** |
| **无数据** | 该期功能未上线 | 整格灰底 + 「需 X 期功能」，**绝不填占位数字** |

**禁止的三种做法**：
1. 数据缺失时显示 `0`（0 是有效值，会让用户以为真的没有）
2. 数据缺失时隐藏该格（用户不知道这里本该有内容）
3. 用上一天的旧数据顶替（不标注就是欺骗）

## 3. 观察池页 `/watch`

### 3.1 布局

```
┌──────────────────────────────────────────────────────┐
│ 观察池   待观察 12 · 埋伏 5 · 启动确认 3 · 持有 2       │  ← 状态计数条
├──────────────────────────────────────────────────────┤
│ [全部] [待观察] [埋伏] [启动确认] [持有] [已移出]        │  ← 状态筛选
├──────────────────────────────────────────────────────┤
│ 代码   名称   状态    入池    停留   板块   评分  操作   │
│ 600986 浙文…  [埋伏]  11-10   3/15   BK0896  74   ⋯    │
└──────────────────────────────────────────────────────┘
```

### 3.2 行内要素

| 列 | 说明 |
|---|---|
| 停留 | `3/15` = 已停留 3 天 / 上限 15 天。**接近上限时标黄**（>80%） |
| 板块 | 带 grade 徽标，点跳板块详情 |
| 评分 | 综合评分，点跳分析台 |
| 操作 | 详情 / 加备注 / 移出 |

### 3.3 详情抽屉

点击某行展开：

- **状态时间轴**：从入池到现在的每次迁移，带 `trigger` 与证据（来自 S8）
- **失效条件清单**：当前生效的条件 + 各自当前值
- **价格走势**：入池以来收盘价迷你图 + MA20
- **同板块其他标的**：横向对比

### 3.4 移出交互（关键）

点「移出」必须弹出原因选择，**四选一，无默认值，不允许取消后不选**：

```
为什么移出？
○ 逻辑破了（触发了失效条件）
○ 触发太慢（超过最长停留）
○ 被更好的标的替代
○ 我判断错了
```

前两项系统已自动判定，弹窗里默认选中；后两项需人工勾。

选「我判断错了」时追加一个可选输入框：「错在哪」。

**这个交互不许简化**。移出原因是判断力画像的原料，省掉它整个观察池就退化成第二个自选股。

### 3.5 已移出列表

单独 tab，显示：代码 / 移出日期 / 停留天数 / 移出原因 / 移出时涨跌。

**按原因分组统计**：`逻辑破了 18 · 太慢 9 · 替代 4 · 判断错 6`。这个统计本身就在告诉用户「我的池子门槛是松还是紧」。

## 4. 策略实验室页 `/lab`

### 4.1 五个 tab（不要拆成五个页面）

| tab | 内容 |
|---|---|
| **策略列表** | 全部策略 + 状态 + 最近结论 |
| **编辑器** | 粘贴源码 + 输出线选择 + 语法检查 |
| **验证** | 五道闸结果（跑闸 / 看历史） |
| **信号** | 每日信号记录 + T+N 跟踪曲线 |
| **批量** | 多标的回测汇总（沿用现有 `batch.py` 能力） |

> **2026-11-16 实现说明**：实际 tab 是「编辑器 / 验证 / 信号 / **跟踪** / 批量」五个，
> 「策略列表」没有单独成 tab —— 它作为**验证 tab 的第一块**（跑闸的入口就在列表行上）。
> 这样做是因为「看策略列表」和「跑闸看结论」是同一个动作的两步，分到两个 tab
> 反而要来回切。`跟踪` 是新增的：`信号` tab 是一张按日期的明细表，`跟踪` 才回答
> 「这个策略最近在变好还是变差」。两者的数据源相同（S11 的 `payload.track`）。

### 4.2 编辑器 tab

```
┌────────────────────────────────────────┐
│ 策略名 [均线突破    ]  类型 ●公式 ○Python │
├────────────────────────────────────────┤
│  1  MA20:MA(C,20);                     │  ← 带行号
│  2  BUY:CROSS(C,MA20);                 │
│                                        │
├────────────────────────────────────────┤
│ 输出线 [BUY ▾]      [语法检查] [未来函数扫描] │
└────────────────────────────────────────┘
```

**「输出线」必须手选，不许自动猜**：公式可能有多条输出线，猜错了信号就全错。默认列出全部输出线让用户选。

**「未来函数扫描」结果分三级展示**：
- 高危红：直接禁止保存
- 中危黄：允许保存但标记「存疑」
- 提示灰：仅告知

### 4.3 验证 tab

五道闸用**纵向步骤条**展示，每道一行：

```
① 未来函数     ✓ 通过    未检测到
② 样本内外     ✓ 通过    样本内 +31% / 样本外 +18% / 衰减 42%
③ 普适性       ✓ 通过    50 只标的中 32 只正收益（64%）
④ 牛熊分段     ! 存疑    熊市段样本不足 60 日，无法判定
⑤ 双轨一致     — 未检验  当前仅公式版

结论：存疑   [查看明细]
```

**符号含义固定**：`✓` 通过 / `✗` 不通过 / `!` 无法检验（`null`）/ `—` 不适用。

`!` 与 `✓` 必须视觉上明确区分——这是 tdx-backtest 把 `SKIPPED` 误当通过留下的教训。

### 4.4 信号 tab

- 顶部：策略选择 + 日期范围
- 主体：每日信号表（代码 / 动作 / 信号价 / T+1 / T+5 / T+10 / 命中）
- 底部：累计命中率曲线 + 与回测命中率的对比线

**必须画"实盘 vs 回测"两条线**。只有一条线看不出策略在衰减。

> **2026-11-16 补齐**：底部曲线原先没做，只有 `跟踪` tab 里的两根静态进度条。
> 现在做了 `/api/lab/track-curve` + `#sig-curve` SVG（`public/js/lab.js` `drawCurve`）：
> - 实盘：按信号日聚合的**累计**命中率折线（未到期与停牌无数据不计入分母，绝不
>   当成「没命中」——否则策略越新、命中率越低）
> - 回测：`backtestWinRate` 是个常数，画成水平虚线叠在同一坐标系里
>
> 只在选定**具体策略**时画：「全部策略」下两条线没有共同基准，混着画没有意义。

### 4.5 批量 tab

沿用现有 `tools/backtest*.py` 的能力，输出：
- 多标的汇总表（正收益占比、平均收益、最大回撤分布）
- 失败标的清单（数据不足/停牌）

**实现对照**

| 文档要求 | 实现位置 | 做法 |
|---|---|---|

| 2 屏内看完 | 同上 | 窄屏 `.cells{gap:6px}` / `.cell{padding:10px 12px}` / 空态 `.nodata-body` 最低高 44px |
| 不出现横向滚动条 | `public/css/style.css` §6b / `public/css/ql.css` §28 | 窄屏 `.hd-right{flex-wrap:wrap}`（分析台/选股器）+ `.hd nav{flex-wrap:nowrap;overflow-x:auto}`（观察池/实验室/板块） |

### 5.3.2 三个只在宽屏才炸的坑（务必别再踩）

**坑 1 · `main` 的两栏栅格被六个页面共用**

`style.css` 里 `main{display:grid;grid-template-columns:318px minmax(0,1fr)}` 本来是
**分析台专用**的两栏壳子（左侧栏 318 + 右主区），但六页的 `<main>` 都会吃到这条规则。
今日一页若不显式重置，1440px 下七格全被塞进那 318px 的栏里，文字竖排成一列；
而 `@media (max-width:1080px)` 会把 `main` 改回单列——于是**手机看着正常、桌面是坏的**，
最难发现的那种坏法。修法：`.today-wrap{display:block}`（acceptance `C26` 守着）。

**坑 2 · 给原生 `dialog` 设 `display:flex` 会盖掉关闭态**

UA 样式是 `dialog:not([open]){display:none}`，特异性 0-1-1；`dialog.drawer{display:flex}`
是 0-1-1 但后出现，直接盖掉。结果观察池/实验室页底部多出一整屏空白的「标的详情」框
（实测页高 1569，加一条 `dialog.drawer:not([open]){display:none}` 后 853）。（`C27` 守着）

**坑 3 · 头部有两套，改一套只修一半**

`today/index/screen` 用 `<nav class="main-nav">`（规则在 `style.css`），
`watch/lab/sector` 用裸 `<nav>`（规则在 `ql.css`）。
375px 下 5 项共需 267px、可用 351px，但换行后「选股器」会孤零零掉到第二行。
两套都要 `nowrap`。（`C32` 守着两处）
